# 托管模式完善记录

日期：2026-10-25。基线：v0.22.0。

## 本轮范围与验收

继续使用现有 stdio app-server，不引入 Codex 终端或 WebSocket 传输。初次实现不修改本机服务；后续按用户授权进行真实联调和本机测试版安装。

1. Codex 的排队发送保持原行为；独立追加操作使用 `turn/steer` 和 `expectedTurnId`，不回退到启动新轮次。
2. 追加要求发送 ID；宿主串行处理，拒绝并发排队/追加。已确认拒绝可重试；确认丢失标记为不确定、终止连接并禁止相同 ID 重发。完成通知早于 RPC 回复时不提前释放运行状态。
3. `item/permissions/requestApproval` 通过人工审批桥处理，批准只授予请求中的权限、仅本轮有效；未知结构拒绝，取消或已解决的请求不发送过时答案。
4. 原始计划、差异和用量事件在前端可读展示，同轮计划/差异更新替换旧内容；累计用量不求和，不把缺失当作零。差异限制渲染行数，保留截断说明。
5. 纯前端兼容旧服务端：只有 `features` 含 `codexSteer` 才显示和调用追加操作；旧请求体不添加字段，缺失事件不显示空指标。
6. 待确认的追加保留原发送 ID，任务结束后仍可只读查询；同一草稿的普通发送也走原追加查询，避免另起轮次重复执行。记录过期、淘汰或宿主重启后只返回未知，不再投递；确认不受后来添加的附件影响。旧 runtime 的迟到结算不修改新执行的状态或审批。
7. 修复 Claude Code 后台审批单独等待时停止无效；修正两种提供方的配置生效提示，当前工作和后台任务结束后，下次发送应用。

## 验证边界

Go 测试通过合成 JSON-RPC 子进程验证协议、真实管道和进程退出；HTTP 测试验证去重、错误、并发和完成竞态；前端测试验证可选能力、异常数据、转义、截断和缺失指标。权限结构核对本机 Codex CLI 0.164.0 生成的 schema。

2026-10-26 已在隔离宿主中完成真实 Codex 追加、去重、停止和扩展权限审批，以及 Claude Write 人工审批；宿主重启后的只读确认验证通过。详见 [验证记录](../verification.md)。发送 ID 去重是有界内存记录，不能跨宿主重启保证；确认查询不会补发丢失的请求。用量展示来自已加载事件中的最新快照，不代表新增订阅统计能力。

真实移动端、真实网络中断，以及 Claude 后台子任务审批尚未端到端验证；相应错误和后台审批停止路径有自动回归覆盖。本机安装保留忙碌会话，按空闲重启机制切换。
