# 会话时间、详情与设置优化方案

状态：已实现。基线为 `48814f0`（Codex 托管支持与下拉框调整）。以下约定已落实到会话时间、侧栏用量、会话详情和全局设置。

## 目标

1. 在侧栏直接判断哪个会话最近有过对话。
2. 打开会话详情即可了解当前执行状态、实际配置和关键统计。
3. 能明确区分本会话设置、提供方默认、原生工具配置和本浏览器偏好。
4. 压缩侧栏用量区，同时保留用量、重置时间与异常状态的可读性。

## 现状与问题

- 侧栏已有名称、目录、提供方、模式、状态和缓存标记，但不显示时间。
- `sessions.updated_at` 随状态设置更新；`store.Append` 单独写入事件。现有统计的 `lastActivityAt` 是所有事件的最大写入时间，不能直接保证等于原始最后对话时间，尤其是导入、同步和宿主重启。
- 顶部状态弹层与会话设置重复展示模型、权限等信息。创建时间、原生 ID 和统计藏在设置表单下方，查信息与改设置相互干扰。
- 生效值、默认来源和下一轮使用值混在一起；原生 CLI 未报告的值容易被“默认”文案表现成已经确认的实际值。
- 全局设置先选择提供方，切换提供方会重新挂载整个设置页面；主机外观和浏览器通知本不需要跟随提供方切换。
- 侧栏 5h / 周用量目前用两行进度条；额度属于 Claude 账户，但页面已经支持多个提供方，需要明确归属。

## 方案一：会话列表显示最近对话时间

列表行保持名称、目录、状态的现有阅读顺序，在底部信息行右侧展示时间，缓存标记降为次要提示。宽度不足时允许元信息换行，不挤掉名称和状态。

| 时间范围 | 显示示例 |
| --- | --- |
| 一分钟内 | 刚刚 |
| 一小时内 | 12 分钟前 |
| 当天 | 14:32 |
| 昨天 | 昨天 18:20 |
| 当年其他日期 | 10-21 09:15 |
| 跨年 | 2025-12-31 |

- 使用浏览器本地时区；悬停、键盘聚焦或详情中可查看完整日期、时间和时区。手机用户可直接从详情读取完整时间。
- 无有效时间显示“时间未知”；无对话的新会话显示“尚无对话”，同时可查看创建时间。
- 默认按最近对话排序，无对话时用创建时间兜底，同时间用稳定键排序。打开页面、改设置、同步旧历史不能让旧会话变成最近对话。
- 流式片段可更新活动信息，但列表顺序在轮次开始/结束等稳定边界更新，避免执行时持续跳行；不改变当前选择、草稿或滚动锚点。
- 第一版不增加日期分组或多种排序开关，先把时间和默认排序做准确。

### 数据约定

增加明确的 `lastConversationAt`，保留现有 `updatedAt` 的状态/兼容语义。后端统一处理时间来源，前端只负责格式化。

- 托管会话：记录用户消息、助手输出及相关执行过程的原始活动时间；排除设置修改、单纯连接/同步、宿主重启提示等管理事件。
- 终端会话：优先使用 transcript 原始时间，不能用本次读取或导入时间覆盖旧对话时间。
- 原生历史：优先读取最后一条有时间的真实对话/执行记录；只有文件修改时间时标注为估算，不能伪装成精确的消息时间。
- `/clear` 保留 CC Remote 对话历史，因此保留最后对话时间，后续新消息再更新。
- 旧数据通过有界迁移/回填处理；列表请求不逐会话扫描全部事件或完整 rollout。需要索引或缓存时依照实际查询补充。
- 统计接口的活动时间与列表字段语义要明确区分，不能直接改动现有通知依赖的 `updatedAt`。

## 方案二：统一会话详情，缩短设置路径

顶部状态摘要继续承担快速浏览和模型/推理强度切换；完整“会话详情”作为统一入口。桌面使用侧面板，手机使用适合窄屏的全屏面板，复用相同信息结构。

| 区域 | 首屏内容 | 次级内容或操作 |
| --- | --- | --- |
| 概览 | 名称、提供方、模式、状态、最后对话时间、项目目录 | 创建时间、复制目录、复制会话/原生 ID |
| 当前执行 | 当前活动、等待操作、排队数、后台任务 | 跳转待处理项、查看任务；仅在有相应能力时展示操作 |
| 配置 | 模型、推理强度、权限/沙箱及其来源 | 修改本会话覆盖、恢复继承、查看下一轮配置 |
| 统计 | 轮次、执行耗时、可获得的 token/上下文 | 已知费用及估算说明、统计范围与更新时间 |
| 管理 | — | 删除会话等低频或危险操作，继续保留确认流程 |

- 模型/推理/权限按行展示“当前值 + 来源 + 编辑”，减少重复标签和大段说明；少量解释放到就近提示。
- 来源明确为“本会话覆盖 / CC Remote 默认 / 提供方原生配置 / CLI 实际报告”。无法获取实际值时显示“未报告”，单独展示配置预期。
- 正在执行时修改设置，明确“下一轮生效”；显示当前执行值与待生效值，保存成功不立即把当前执行值替换掉。
- token 是否已知与费用是否已知分开判断，缺数据用“未提供”，不显示误导性的 0；区分账户订阅额度与单会话统计。
- 查看详情默认无须进入编辑态；编辑后才出现保存/取消。离开有未保存修改的区域时提供清晰处理，不能默默丢失。
- 原生历史提供只读详情和导入入口，不展示不可执行的设置/控制。

## 方案三：按作用范围重组全局设置

一级导航固定为以下三类，切换提供方只影响提供方相关区域：

1. **会话默认**：Claude / Codex 子选项，集中展示默认模型、推理强度和权限/沙箱。明确只影响继承默认的会话，以及生效时机。
2. **主机**：名称、颜色、图标；提供方安装/连接状态、版本、配置来源。服务诊断、订阅详情和历史曲线继续归“服务状态”，通过链接进入。
3. **浏览器**：语言、通知、发送快捷键等本设备偏好。集中展示已有设置，先核实各字段当前存储范围，避免改布局时顺带改变同步语义。

Claude 原生用户配置放到 Claude 区域的“原生配置”高级分组，明确会影响外部 CLI；Codex 尚未实现的原生配置编辑不展示为空表单。高级配置路径、原生参数和长 ID 默认折叠，支持按需展开与复制。

## 方案四：侧栏用量单行双圆环

- 将现有两行横向进度条改为一行两个摘要：`圆环 + 5h + 百分比`、`圆环 + 周 + 百分比`。圆环建议直径 28–32 px，整行点击区域至少 44 px 高。
- 两项平分可用宽度，数字使用等宽数字；正常侧栏宽度下保持一行，窄侧栏也不截断百分比。
- 明确百分比表示“已使用”，圆环填充方向保持一致；保留现有高用量颜色，并用数字表达状态，不能只依靠颜色。
- 控件可访问名称注明“Claude 订阅用量”，在 Codex 会话内也不会误认为是 Codex 额度。数据源仍为现有 Claude 用量接口。
- 悬停/聚焦展示完整用量、重置时间和更新时间；点击整行进入现有服务状态详情，手机不依赖悬停获得信息。
- 加载、未知、请求失败或过期时使用中性圆环、`—` 和状态说明，不画成 0%。保留现有缓存、退避和数据源限制。

## 实施顺序与验收

1. **时间与列表**：先锁定时间语义，补齐来源、回填和排序测试，再实现时间格式和列表布局。验证原生历史导入后不会被误认为刚刚对话，设置修改与重启不影响对话排序。
2. **侧栏用量**：复用现有接口与详情入口完成双圆环；验证 0%、100%、未知、过期、错误以及窄侧栏、中英文和触屏布局。
3. **详情与设置**：先统一信息模型与配置来源，再实现详情面板和设置分组，逐步移除重复入口。覆盖运行中改设置、默认继承、版本冲突和未保存离开。

每一步保持独立提交。涉及行为和数据语义的变更先补有意义的回归；完成后运行相关 Go 测试、前端测试、TypeScript 和两种前端构建，并在可用浏览器中验证桌面/手机。不增加依赖，不扩展 Codex 终端接力或订阅额度。
