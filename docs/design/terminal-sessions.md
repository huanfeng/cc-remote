# 设计：终端会话（宿主持有的交互式 Claude）

状态：已确认方向，待实施（2026-10-16）

## 目标

同一个任务在本地终端和网页上都能继续处理，两边切换时，子 agent 等长时间运行的任务不中断。

用户的期望：

- 本地能在真实的 Claude Code 终端里工作。
- 离开电脑后，能在手机或网页上接着处理同一个会话。
- 切换时不中断进行中的工作，包括后台 agent。

## 结论先行

新增一种会话类型「终端会话」。宿主在伪终端（PTY）里运行交互式 `claude`，并一直持有这个进程。本地终端、网页结构化视图、网页终端都只是接到这个进程上的「前端」，接入和断开都不影响进程本身。

原型已在 Windows（ConPTY）和 Linux 上通过 7 项检查：

- 启动
- 普通消息
- 多行消息
- 忙碌时发送
- Esc 中断
- `/compact`
- 前端断开重连时后台 agent 继续运行

## 与现有两种模式的关系

| | 托管会话（现有） | 共享会话（现有） | 终端会话（新增） |
|---|---|---|---|
| Claude 进程 | 宿主启动的 `claude -p`，没有界面 | 用户终端里的交互式 `claude` | 宿主在伪终端里启动的交互式 `claude` |
| 谁持有进程 | 宿主 | 用户的终端窗口（关掉窗口就结束） | 宿主（关掉终端不影响） |
| 网页消息怎么送达 | stdin（stream-json） | Channels 通知 | 作为键盘输入写进终端 |
| 斜杠命令和 Esc | 透传，可以执行 | 不能执行 | 可以执行，与本地键盘一样 |
| 本地终端 | 没有 | 有，但只有那一个窗口 | 随时接入、随时断开，可以同时接多个 |
| 网页状态从哪来 | stream-json 事件 | transcript 加 hook | transcript 加 hook（复用共享模式的代码） |

长远看，终端会话可以取代共享会话：两者都是交互式进程，但终端会话没有 Channels 的限制。托管会话保留，作为不需要终端的轻量模式。

## 总体结构

```
                      ┌────────────────── cc-remote 宿主 ──────────────────┐
                      │                                                    │
 本地终端 ─ attach ──►│  终端会话运行器（每个会话一个）                     │
  （可多个）          │   ├─ 伪终端：交互式 claude（--session-id/--resume） │
                      │   ├─ 输出分发：原始字节 → 所有已接入的终端前端       │
 网页终端 ─ WebSocket►│   ├─ 输入合并：键盘输入 / 网页消息（整段粘贴 + 回车） │
                      │   ├─ 尺寸：本地终端优先，其次最近活跃的网页           │
 网页结构化视图 ◄─────│   └─ 状态：hook（开始/结束/等待）+ 进程存活          │
  （现有界面）        │                                                    │
                      │  transcript 同步（复用 syncTranscript）→ events 表   │
                      │  审批/提问（复用 PermissionRequest hook）→ 网页卡片   │
                      └────────────────────────────────────────────────────┘
```

## 详细设计

### 1. 启动与配置（复用共享会话的启动器）

- 复用 `internal/channel/launch.go` 里 `writeConfig`、`hookSettings` 写临时配置的逻辑，也复用 `ask.json` 和 binding file。去掉 MCP 配置和 `--dangerously-load-development-channels`。
- hook 增加以下几项，都由新的子命令 `cc-remote terminal-state-hook` 处理，转发给宿主：
  - `UserPromptSubmit`：一轮开始。
  - `Stop`：一轮结束。
  - `Notification`：Claude 在等用户，比如权限对话框或空闲提示。
  - `SubagentStop`：子 agent 结束。
- 启动参数：`--session-id <uuid>`（新会话）或 `--resume <uuid>`（恢复）、`--settings <临时 settings>`，以及模型、推理强度、权限模式这些偏好。
- **环境变量**：过滤掉上一级 Claude Code 会话的标记，包括 `CLAUDECODE`、`CLAUDE_CODE_CHILD_SESSION`、`CLAUDE_CODE_SESSION_ID`、`CLAUDE_PID`、`CLAUDE_CODE_ENTRYPOINT`、`CLAUDE_CODE_MESSAGING_*` 等。原型里遇到过：继承了这些标记的子进程会变成「子会话」，不保存 transcript。托管会话的启动也应该一并过滤。
- 伪终端用 `github.com/aymanbagabas/go-pty`，同一套接口覆盖 ConPTY 和 Unix pty，原型里用的就是它。注意：Windows 上要先用 `exec.LookPath` 解析出 claude 的绝对路径。

### 2. 目录信任对话框

交互式 claude 第一次进一个目录时会问「是否信任这个文件夹」，**默认选中的是「不，退出」**。

- 网页新建终端会话时，明确提示「将信任此目录，Claude 可以读写和执行其中的文件」，用户确认后才创建。这和现在新建托管会话时选目录的意思一致，只是把确认说清楚。
- 运行器识别到这个对话框后（去掉空格匹配「trust this folder」），先按「下」，确认光标已经在「Yes」上，再按回车。确认不了就不动，交给用户在终端前端里手动处理。
- 其它预料之外的对话框也一样：网页终端就是兜底。这是终端会话比托管会话更稳的一点：任何界面上的状态，用户都能直接看到并处理。

### 3. 网页消息与命令

- 普通消息：用整段粘贴（`ESC[200~ … ESC[201~`）写入后再按回车，多行内容会作为一条消息。原型已验证。
- 斜杠命令：方式相同，`/compact`、`/clear`、`/model`、自定义命令等都能真正执行。
- 停止：写入 Esc。连续第二次停止，或 Esc 之后 15 秒仍在执行，写入 Ctrl+C。
- 附件：文件保存在宿主的会话附件目录里，在消息中以 `@路径` 引用。
- 记录：网页消息不再由发送端点直接写进记录，而是先显示为「等待处理」。transcript 里出现对应的用户消息后，按文本匹配转成正式记录，避免重复显示。
- **与本地键盘同时输入**：如果某个终端前端在最近 2 秒内有按键，说明本地可能正在输入框里打字。网页消息先排队，等本地停顿后再写入，避免两段输入混在一起。

### 4. 状态判断

| 状态 | 依据 |
|---|---|
| 执行中 | `UserPromptSubmit` 之后、`Stop` 之前；或 transcript 里出现了新的助手输出 |
| 等待操作 | 有未回答的审批或提问；或 `Notification` 报告了权限请求 |
| 空闲 | `Stop` 之后，且没有等待中的请求 |
| 离线 | 进程不在（已退出或宿主重启后还没拉起） |

后台 agent 在会话空闲时继续工作，不算「执行中」，这和托管会话阶段 2 的规则一致。

### 5. 审批、提问与计划确认

- 提问（AskUserQuestion）和计划确认（ExitPlanMode）：原样复用共享会话的 `PermissionRequest` hook（`askhook.go`）和 `channelInteraction`、`resolve`、`finishSharedLocked` 这一套。网页和终端都能回答，以先回答的为准。
- 普通工具审批：`PermissionRequest` hook 的匹配范围扩大到所有工具（matcher `*`），`channelInteraction` 增加 `approval` 类型。网页显示审批卡片（允许、拒绝、交给终端），终端里同时显示原生对话框，以先回答的为准。
- 已实测（Claude Code，haiku）：hook 等网页时终端对话框照常可用；网页允许、网页拒绝、终端 Esc 拒绝（网页卡片约 2 秒内撤回）都正确；前台和后台子 agent 的工具审批也能在网页回答。后台子 agent 的对话框不立即显示在主界面，所以不能凭屏幕判断对话框已关闭，hook 改读子 agent 自己的 transcript。
- 实测：终端批准一个 30 秒的命令后，工具约 2 秒后开始执行，Claude Code 显示「running PermissionRequest hooks」，tool_result 30 秒后才写入。所以主 agent 的审批改由宿主看屏幕撤卡：对话框（含「Esc to cancel」）出现过、又离开 2 秒即撤回，实测撤卡时间从 34 秒降到约 4 秒；对话框没人回答时 15 秒内不误撤，网页允许照常生效。

### 6. 网页结构化视图

- 复用共享会话的 `syncTranscript` 和 `applyTranscriptLocked`：读取 transcript，增量解析，去重后写进 events。触发时机：宿主定时器每 1 秒一次，加上各个状态 hook 到达时。
- 子 agent：交互式会话把子 agent 的过程写在 `<会话>/subagents/` 下单独的文件里。需要补上读取这些文件，嵌套显示到 Agent 卡片里（这也是阶段 2 留下的待办，终端历史和共享会话会一起受益）。任务面板改为从子 agent 文件和 `SubagentStop` hook 推导状态。
- 前端沿用现有的分页、缓存、工具卡片、子 agent 卡片，不需要大改。

### 7. 终端前端

#### 本地：`cc-remote attach`

- `cc-remote attach [会话]`：接入宿主上的终端会话。不带参数时列出会话供选择。
- 原始模式转发键盘输入和屏幕输出，窗口尺寸变化时通知宿主。
- 按 Ctrl+] 断开，会话和其中的 agent 继续运行（和 tmux 的 detach 一样）。
- 接入时让 Claude 重绘一次：先发一次尺寸变化，必要时补一个 Ctrl+L，新前端就能看到完整画面。原型验证过，重绘请求之后能收到输出。
- `ccr`（现在启动共享会话）以后可以改为「在当前目录新建或恢复终端会话，并立即 attach」。这样从本地启动的会话天然就能在网页上继续，关掉终端也不会结束。是否这样改，见下面「待确认问题」。

#### 网页终端

- 会话页面增加「终端」视图，用 xterm.js（通过 pnpm 安装，打包进前端），和结构化视图可以随时切换。
- 连接用 WebSocket（`github.com/coder/websocket`）。浏览器不能给 WebSocket 设置请求头，所以令牌放在连接后的第一条消息里，同时检查 Origin。
- 手机上以结构化视图为主，终端视图用来处理意外的对话框或做细节操作。

#### 尺寸规则

同一时刻只能有一个尺寸。有本地终端接入时只有本地终端能改尺寸（宿主拒绝网页的 resize，`size` 通知带 `held: true`，网页改为跟随）；多个本地终端之间以最近调整窗口或打过字的为准（打字时宿主恢复该终端上次报告的尺寸）。没有本地终端时，以最近调整尺寸的网页为准。这个规则只影响终端画面，网页结构化视图不受影响。

### 8. 生命周期

- 进程在网页或 `attach` 第一次需要时启动，之后**默认一直保留**，和交互式 Claude 本身的行为一致；网页提供「结束会话」手动结束。
- 可选的空闲回收（设置项，默认关闭）：没有前端接入、没有后台任务、空闲超过设定时间后退出进程，下次需要时用 `--resume` 拉起。
- 提示缓存：缓存在 Anthropic 服务端，按请求前缀匹配，有效期 5 分钟（部分配置为 1 小时），与进程是否存活无关。实测（`-p` 模式，2026-10-16）：进程退出后用 `--resume` 恢复，第一轮读取缓存 56k、新写入 7k；工作目录的 git 状态变化后再恢复，读取 63k、新写入 0.7k。也就是说，恢复会重建相同的请求前缀，只要还在有效期内就能命中，回收进程本身不会让缓存失效。真正让缓存失效的是时间，以及 CLAUDE.md、MCP 工具、设置的变化。交互模式在阶段 1 复测。
- **宿主重启会结束所有终端会话的进程**，包括其中正在运行的 agent。`cc-remote update`、服务重启都会触发。缓解措施：
  - `update` 和服务重启前，如果检测到有终端会话正在执行或有后台任务，先提示并要求确认（或加 `--force`）。
  - 重启后会话显示为「离线」，下次使用时用 `--resume` 恢复上下文。被中断的任务在任务面板中标记为「已中断」。
  - 想要宿主重启后进程依然存活，需要把进程托管给独立的守护进程（类似 tmux server）。复杂度明显更高，第一版不做，以后视需要再评估。

### 9. 安全

- 终端流等同于在宿主上执行任意命令的能力，和访问令牌的权限相同。鉴权沿用 Bearer 令牌，WebSocket 额外检查 Origin。
- 临时配置目录、`ask.json` 的权限和清理方式沿用共享会话的做法（0600，退出即删，残留目录 24 小时后清理）。
- 原型在 `~/.claude.json` 里为测试目录留下了信任记录。正式实现只信任用户在网页上确认过的目录。

## 实施阶段

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| 1. 运行器与网页接入 | 伪终端运行器、配置和 hook、状态判断、网页消息和命令写入、transcript 同步、提问和计划确认复用、目录信任确认、环境变量过滤；新建会话时可选「终端会话」 | 网页上能完成发消息、`/compact`、停止、回答提问；忙闲状态正确；宿主重启后能恢复上下文 |
| 2. 本地 attach | `cc-remote attach`、Ctrl+] 断开、尺寸同步、接入时重绘、与网页同时输入时的排队 | 本地接入、断开、再接入，后台 agent 不受影响；本地和网页交替发消息不乱序 |
| 3. 网页终端 | xterm.js 视图、WebSocket、手机上的适配 | 网页终端里能处理意外对话框；切换视图不影响会话 |
| 4. 补全 | 工具审批经 hook 送到网页、子 agent 文件嵌套显示、任务面板、`update` 前的忙碌提示 | 非 bypass 权限模式下网页能审批；子 agent 过程可见 |
| 5. 迁移 | 「终端会话」成为新建会话的默认选项；`ccr` 改为启动终端会话；共享会话标记为旧模式 | 现有托管会话和共享会话照常使用 |

阶段 1 和阶段 2 完成后就能满足核心诉求：本地和远程都能接着处理，切换不中断。

## 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| Claude Code 的界面或 hook 行为随版本变化 | 对话框识别、状态判断失效 | 状态以 hook 和 transcript 为主，屏幕识别只用于极少数对话框；网页终端兜底；为关键流程写回归测试，升级 Claude Code 后重跑原型脚本 |
| 工具审批时 hook 和终端对话框同时存在 | 可能卡住或重复 | 已实测两边可并存，以先回答的为准；网页卡片可「交给终端」 |
| 本地和网页同时输入 | 两段输入混在一起 | 本地有按键时网页消息排队；网页消息整段粘贴 |
| 宿主重启结束进程 | 运行中的 agent 被中断 | 重启前提示确认；重启后用 `--resume` 恢复；独立守护进程以后再评估 |
| 每个会话一个常驻交互进程 | 内存占用（每个大约几百 MB） | 默认保留，用户可手动结束或开启空闲回收；同时运行的终端会话设置上限，超出时提示 |
| Windows ConPTY 的差异 | 按键、尺寸行为不一致 | 原型已在 ConPTY 上通过；运行器测试在 Windows 和 Linux 上都跑 |

## 决定

1. `ccr`：暂不改动。阶段 1–2 先提供 `cc-remote attach` 作为新入口，用户实际试用后再决定 `ccr` 是否改为启动终端会话。
2. 进程回收：默认一直保留，手动结束；空闲回收作为可选设置，默认关闭（理由见「生命周期」里的缓存实测）。
3. 共享会话：终端会话稳定后逐步下线。
