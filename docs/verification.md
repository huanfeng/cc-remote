使用宿主现有 CLI 登录，未更改全局或项目 Claude 设置。测试在独立的 `.test-data/workspace-a` 和 `.test-data/workspace-b` 目录中执行。

1. 在 Web 创建会话 A，发送测试消息，实际收到 `CC_REMOTE_OK`。
2. A 的下一轮询问上轮指定的暗号，实际收到 `CC_REMOTE_734`，验证精确恢复上下文。
3. 在 Web 创建会话 B；A、B 在列表中分别显示状态，可切换。
4. B 调用 `AskUserQuestion`，前端显示蓝色/绿色选项；点击蓝色并提交后，CC 实际回复「蓝色」。
5. B 调用 Write，前端显示目标路径和内容审批卡；点击「允许本次操作」后，测试目录的 `cc-remote-smoke.txt` 实际写入 `CC_TOOL_OK`。
6. 最终宿主读取本机 63 个原生会话，测试会话 A 的原生历史中可读取到恢复暗号的回复。
7. 第二个宿主尝试用另一个端口打开同一个数据目录，被独占锁拒绝。

自动测试不调用模型；上述真实调用使用宿主的 CC 账户。测试数据不进入默认生产数据目录。

## 验证边界

- Windows 完成真实 CLI 和浏览器集成验证；Linux 只完成交叉构建和平台代码检查。
- 原生历史读取依赖 JSONL 兼容层；不代表能实时接管任意原生会话。
- 不涵盖旧版 CLI、所有用户自定义 Hooks/MCP、浏览器通知或移动设备的系统级 PWA 安装。截图输入已在下述 V3 中补充验证。
