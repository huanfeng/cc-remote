# 使用说明

本文是 [README](../README.md) 的详细补充。配置项见 [configuration.md](configuration.md)，工作原理与限制见 [architecture.md](architecture.md)。

## 项目终端

项目终端默认可用。终端和 `ccr run` 都以所连接宿主的服务账户权限运行。

从会话标题栏或侧栏项目组打开「项目终端」。同一主机和项目内的会话共用一个默认 Shell。收起面板或断开网页连接后，Shell 仍在后台运行，重新打开即可接回。需要结束进程时，在面板里选择「结束终端」，或执行 `exit`。多个页面可以查看同一终端，输入和尺寸由持有控制权的页面决定。

用标签栏的「新建终端」在同一项目打开独立标签。终端和窗格按项目编号，默认名称为「终端 1」「终端 2」等。「运行中的终端」会同时显示名称和所属项目。右键标签可原位编辑名称，按 Enter 保存，按 Esc 取消。右键选择「结束终端」或中键点击标签，会结束该标签下的所有窗格。最后一个标签结束后面板关闭，再按快捷键会打开新 Shell。用 `ccr shell attach` 可以从本地终端选择并接入同一个窗格。

用标签栏的搜索按钮查找当前窗格保留的输出。按 Enter 查找下一个匹配，按 Shift+Enter 查找上一个匹配。搜索栏也可以暂停跟随输出或回到最新一行。

右键标签栏空白处可新建终端。右键终端输出区域可复制选区、搜索、跳到最新输出或结束该窗格。右键标题栏可最小化面板、重置布局或结束当前项目的所有终端。

桌面布局点击标签栏的「左右分屏」或「上下分屏」，会把当前窗格再分成两部分，并聚焦新窗格。可混合两种方向，使用「切换到下一个窗格」循环切换，也可从标签右键菜单指定窗格或改变当前分屏的方向。关闭窗格时相邻分支会补上空位。旧版宿主仍支持每个标签最多两个窗格。

会话标题栏的项目终端图标显示当前项目打开的终端数，分屏窗格也计入。绿色徽标表示至少有一个终端进程在线。终端面板内可按 `Ctrl+Shift+Enter` 新建标签，按 `Ctrl+Shift+→` 左右分屏，按 `Ctrl+Shift+↓` 上下分屏。

在桌面布局中，点击会话区会自动收起浮动终端，终端进程仍在后台运行。点击终端标题栏左侧的图钉可固定面板，固定后仍可手动最小化。

在项目终端内直接运行 `ccr shell` 会提示当前已在终端中。可以运行 `ccr shell attach` 选择其他窗格。

项目终端和会话终端共用「设置 → 外观与交互 → 终端配色」。默认使用深色，也可选择浅色、深海蓝、暖棕或跟随应用主题。设置保存在当前客户端。

桌面应用可用 `Alt+F` 开合，Web 使用 `Ctrl` 加反引号。可在界面设置里改键。宿主重启时仅保留当时打开的标签、分屏和启动目录，重新接入时启动新 Shell。正在运行的命令和输出缓冲随原进程结束。

桌面布局可拖动标题栏移动面板，从边缘或角落调整大小。位置和大小会保存在当前客户端，也可在终端菜单里重置。收起再展开时，终端保留当前画面、清屏状态和滚动位置。桌面布局保留最多 10,000 行回滚，移动布局保留最多 5,000 行。刷新网页或断线时，宿主按游标补发保留范围内的输出，每个运行最多保留 4 MiB 或 16,384 个输出事件。

### 用 CLI 执行命令和管理项目终端

| 命令 | 行为 |
| --- | --- |
| `ccr run -- git status --short` | 在宿主上执行一次命令，转发标准输入、标准输出和错误输出，并返回该命令的退出码 |
| `ccr shell` | 创建或打开当前项目的默认 Shell，也可以从 Web 接入同一个进程 |
| `ccr shell ls` | 列出当前宿主记录的 Shell 和状态 |
| `ccr shell attach` | 选择当前宿主上正在运行的 Shell，当前项目排在前面。按 `/` 可按名称、目录或 ID 筛选 |
| `ccr shell attach <ID>` | 用完整 ID 或唯一前缀直接接入指定 Shell |
| `ccr shell attach --cwd <目录>` | 接入指定项目正在运行的默认 Shell |
| `ccr shell stop [ID]` | 结束 Shell 进程，省略 ID 时按当前目录查找 |

按 `Ctrl+]` 可以从 CLI 脱离并让 Shell 继续运行。在 Shell 内执行 `exit` 也会结束进程。结束后可用 `ccr shell` 从启动目录重新打开。

使用 `--host` 连接其他主机。如果本机目录在宿主上不存在，在 `run` 或 `shell` 后加 `--cwd` 指定宿主路径。`run` 按原样传递程序名和参数，用到管道或重定向时可以显式调用宿主的 Shell，例如 `ccr run -- sh -c 'printf hello | wc -c'`。

## 两种会话

| | 终端会话 | 托管会话 |
| --- | --- | --- |
| 启动方式 | 在项目目录运行 `ccr`，或网页「新建」（默认即终端会话） | 网页「新建」选「托管会话」 |
| 进程 | 宿主持有一个交互式 Claude Code，本地终端随时接入 | 每轮一个 `claude -p` 子进程，用 `--resume` 恢复上下文 |
| 终端 | 原生终端界面，终端和网页都能发消息；关闭终端不会停止它 | 无终端，全部在网页操作 |
| 停止生成 | 终端 Esc，或网页「停止」 / Esc 键 | 网页「停止」 / Esc 键 |
| 模型 / 权限修改 | 终端 `/model`、`/effort`、Shift+Tab，或网页标签 | 网页会话设置，下一轮生效 |
| 用量统计 | 状态栏数据（模型、上下文、费用） | 有费用、tokens、耗时 |

### 用 ccr 启动

`ccr` 与 `cc-remote` 接受同样的参数。直接运行打开当前项目的选择器，没有可接入的终端时可选 Claude Code 或 Codex 新建。

```sh
ccr
ccr ls                                            # 跨项目浏览最近的终端会话
ccr --new                                         # 选择 Claude Code 或 Codex 并新建终端
ccr --resume <原生ID>                               # 根据原生会话 ID 自动识别 Agent 并恢复
ccr claude --new --model sonnet --prompt "修复登录页" -- --add-dir ../lib
ccr codex                                         # 打开或新建宿主上的 Codex 终端
ccr codex --new --supplier <供应商ID>                 # 指定供应商，省略时可手动选
ccr claude resume <原生ID>
ccr codex resume --last                           # 继续当前项目最近的 Codex 历史
ccr session list --agent codex
ccr session attach <CCR会话ID>
ccr local --supplier work -- --help               # 在当前终端运行 Claude Code
```

- `claude` 与 `codex` 按项目和 Agent 查找在线终端。需要另开一条会话时加 `--new`，指定宿主目录用 `--cwd`。原生启动选项放在 `--` 后，首条消息用 `--prompt`。
- 选择器按最近活动显示会话，可用方向键、编号加回车、`/` 筛选、`r` 刷新、`q` 或 Esc 退出。选中「新建」可以另开终端。选择离线会话会提示如何恢复原生历史。
- `session attach` 使用 `session list` 中的 CCR 会话 ID，也接受唯一 ID 前缀。`resume` 使用 Agent 的原生历史 ID，省略 ID 可从当前项目选择。已有其他终端接入时会询问是否继续。
- Claude Code 和 Codex 都可在新建终端时选择供应商或用 `--supplier` 指定。用 `ccr profile ls --app codex` 查看 Codex 供应商 ID。Codex 恢复时沿用已记录的供应商，外部历史没有供应商记录时使用宿主原生配置。信任和审批由 Codex TUI 处理。Claude Code 首次进入未信任的目录时会询问信任。
- 连接选项放在命令前，例如 `ccr --host https://ccr.example --data-dir /path/to/data session list`。前台宿主用 `ccr serve`，服务管理使用 `ccr status`、`ccr service` 等命令。

- 接入本机宿主时，Claude Code 输出里提到的本机文件（绝对路径，如 `C:\Users\me\shot.png`、`/home/me/app/main.go`）可以点击打开：`ccr` 把它们标成终端超链接（OSC 8）。只在已知支持的终端里启用（Windows Terminal、VS Code、iTerm2、WezTerm、kitty、Ghostty、Alacritty、JetBrains、VTE 系终端），tmux / screen 里不启用；超链接不占位置，画面不变。用 `CC_REMOTE_HYPERLINKS=1` 强制开启、`=0` 关闭（同时关闭下面的点击打开）。
- Claude Code 的全屏界面会接管鼠标（点击用来展开工具调用等），终端此时不会自己打开链接。所以 `ccr` 会记住当前画面：**Ctrl+点击**（与 Windows Terminal 打开链接的习惯一致）落在本机存在的文件路径上时，由 `ccr` 用默认程序打开该文件，这次点击不再交给 Claude Code；普通点击照常交给 Claude Code（展开工具调用、在输入框里定位等）。这适用于任何终端；工具调用里的相对路径（如 `Update(web/src/App.tsx)`）按会话目录查找，被折到下一行的长路径点任意一段都可以。其它点击、拖动和滚轮也照常交给 Claude Code。
- 旧的共享终端（Claude Code 在你的终端里运行、网页经 Channels 接入）已移除；之前的共享会话已自动转为终端会话，可用 `ccr claude resume` 恢复原来的上下文。

### 托管会话

1. 登录网页，点击「新建」，输入名称和**宿主上已存在的绝对目录路径**，可选模型、推理强度、权限模式。
2. 发送任务；执行期间可以切到其它会话，会话之间可以并行。执行中可以继续发送消息（按钮显示「排队」，最多 5 条），由 Claude 排队，并在下一轮合并处理；多个设备同时发送也会按顺序送达。「停止」只中断当前一轮，排队的消息会继续；再按一次停止会结束进程。
3. Claude 请求审批或提问时，在会话中的操作卡片里回答。「允许」只同意本次请求；待回答的请求最多等待约 30 分钟。
4. 下一条消息自动用原 Claude 会话 ID 恢复上下文。
5. 刷新页面或关闭浏览器不会停止任务，消息保存在宿主的 SQLite 中。
6. Claude 调用子 agent 时，对话里显示一张子 agent 卡片：类型、任务描述、状态、工具次数、tokens 和耗时，运行中显示当前进度。展开后可以看到任务说明、子 agent 自己的消息和工具调用，以及最终结果。后台 agent 运行时会话本身可以继续使用，卡片和顶栏的任务按钮会显示「运行中」；点任务按钮打开「子 agent 与后台任务」面板，选择一项会跳转到对应的卡片或命令。

### 终端会话

宿主在伪终端（Windows 为 ConPTY）里持有一个交互式 Claude Code。网页和本地终端都可以接入同一个进程，切换前端时进程不会重启，子 agent、后台任务等长时间运行的工作也不会中断。设计说明见 [design/terminal-sessions.md](design/terminal-sessions.md)。

1. 网页「新建」，选「终端会话」，填写目录并勾选「信任此目录」（等同于在终端里确认信任此文件夹）。
2. 对话来自 Claude Code 的记录，消息以粘贴的形式送进终端。Claude 正在工作时发送的消息会显示「排队」。Claude 弹出权限框或提问框时，网页消息会先等待，等对话框关闭后再发送，以免误答对话框。工具权限审批、AskUserQuestion 和计划确认都可以在网页回答，也可以「交给终端」。AskUserQuestion 也可以选「先聊聊」：不作答，告诉 Claude 你想先讨论这些问题（同终端里的 Chat about this），托管会话同样可用。「停止」相当于按 Esc，15 秒内再按一次相当于 Ctrl+C。
3. 点击标题栏的模型等标签打开会话状态，选「在本地终端接入」，复制接入命令，在宿主上运行即可在本地终端中操作同一个 Claude Code：

   ```sh
   ccr claude --new --title 修复登录 --model sonnet
   ccr claude resume <原生ID>
   ccr session attach <CCR会话ID>
   ```

   用 `ccr --resume <原生ID>` 可恢复 Claude Code 或 Codex 的历史对话，宿主会自动识别 Agent 并使用原目录。也可以显式指定 Agent，例如 `ccr claude resume <原生ID>`。网页「终端历史」里的会话也可以「以终端会话继续」。

   按 `Ctrl+]` 断开，Claude Code 继续运行。多个前端可以同时接入。终端尺寸以本地终端为准：多个 `ccr` 同时接入时，以最近调整过窗口或打过字的那个为准，网页不会改动它。Windows 的 ConPTY 只发送变化的字符，终端偶尔会留下没刷新的字符：每轮回复结束时会自动整屏重画，也可以按 `Ctrl+L`。
6. 网页标题栏显示 Claude Code 状态栏数据：模型、推理强度、上下文用量（圆环，60% 起变黄、80% 起变红）、时长和费用；Claude 工作时显示和终端相同的状态行（如 `Composing… (8m 33s · ↓ 26.2k tokens)`）。终端里的状态栏仍是你自己配置的那个。
7. 点模型或推理强度标签直接弹出列表切换（托管会话同样可用，作用于下一轮）。终端会话里相当于执行 `/model`、`/effort`：切换模型会让当前对话的提示缓存失效，网页会先提示，确认后由宿主替你确认 Claude Code 的「Switch model?」。注意 Claude Code 会把 `/model` 选择的模型保存为新会话的默认值（写入 `~/.claude/settings.json`），和在终端里执行一样。输入框左下角的 `/` 按钮打开命令列表。
8. 一轮结束后 Claude Code 在输入框里给出的下一步建议（灰色文字）显示在网页输入框上方：点击直接发送，「编辑」填入输入框。
9. Claude Code 的 recap（离开一段时间后它写下的「你离开期间」回顾）显示在对话里，终端历史同样显示。终端会话里，宿主在没有终端接入、网页也没有打开这个会话时告诉 Claude Code「失去焦点」，回来时恢复，所以 recap 和在本地终端里一样会出现（是否生成由 Claude Code 决定，可在 /config 关闭）。
4. 进程默认一直保留。宿主重启（包括 `cc-remote update` 升级）时，停止前正在运行的终端会话会在宿主恢复后自动用 `--resume` 重新启动；接入中的 `ccr` 不会退出，显示「宿主正在重启」，等宿主恢复（最多 3 分钟）后自动重新接入。Claude Code 自己退出的会话，可从命令行用 `ccr claude resume` 或在网页发送消息恢复上下文，提示缓存仍然有效。还没发过消息的会话会以全新会话启动。
5. 在终端里执行 `/clear` 或 `/resume` 时，网页会跟随新的 Claude 会话 ID。切换到的 Claude 会话若正被另一个网页会话使用（在执行、等待回答或 Claude Code 还在运行），网页不会跟随并提示；空闲的会话会自动让出：它的网页历史保留，下次继续时开始新的 Claude 对话。

#### 网页终端视图

终端会话的标题栏右侧有「对话 / 终端」切换。终端视图直接显示宿主上的 Claude Code 界面（xterm.js），和 `ccr` 看到的是同一个画面，可以使用全部功能：`/` 命令菜单、Shift+Tab 切换模式、Esc 中断、权限框和各种对话框。每个会话分别记住选择的视图。会话未运行时打开终端视图会启动 Claude Code。

- **终端尺寸**：终端只有一个尺寸。有本地终端（`ccr`）接入时尺寸由它决定，网页终端视图只「跟随本地终端」，缩放字号显示，不会把本地终端挤乱。没有本地终端接入时，以最近调整的网页为准：电脑上打开终端视图或在其中打字时，终端改为本窗口的大小；另一个网页改了尺寸后，本视图切换为「跟随」，点「使用本窗口尺寸」或直接打字即可取回。
- **手机**：默认只跟随、不改尺寸，按电脑上的列数缩小显示，用 A− / A+ 调整大小并左右滑动查看，不影响电脑上的终端。打开「适配本机」后，终端改为手机的大小（电脑上的终端也随之变化），之后在手机上按键会再次取回尺寸。
- **手机输入**：点终端不会弹出键盘。底部输入框支持中文输入法，「发送」把文字连同回车送进终端（多行文字作为一次粘贴），内容为空时只发送回车；上方一行是手机键盘缺少的按键：Esc、Tab、Shift+Tab、方向键、Ctrl+C、回车。
- **复制粘贴**（电脑）：选中文字后按 Ctrl+C 复制，没有选中时 Ctrl+C 照常发给 Claude Code；Ctrl+V 粘贴。
- 页面切到后台时断开，回来自动重连；宿主重启后同样自动重连。Claude Code 退出时显示「已退出」，点「重新启动」再启动它。
- 只显示当前屏幕和此后的输出，更早的内容在对话视图里看。网页终端不计入 `ccr` 的「已有终端接入」提示。

#### 在 Herdr 里使用

[Herdr](https://herdr.dev) 是在终端里并排运行多个 agent 的复用器，会在侧栏显示每个 pane 里 agent 的状态，并在 agent 等你回答时提醒。直接在 Herdr 的 pane 里运行 `ccr` 即可：Claude Code 实际运行在宿主上，Herdr 看不到它，所以接入期间 `ccr` 把宿主掌握的会话状态上报给 Herdr：

| 会话状态 | Herdr 显示 |
|---|---|
| 执行中 | 工作中（working） |
| 等待操作（审批、提问、计划确认） | 需要回答（blocked） |
| 空闲 | 空闲（idle） |

- 在手机或网页上回答了待答请求后，Herdr 里的「需要回答」随之消失；状态来自宿主的 Hook 与记录，比 Herdr 看屏幕判断更准确。
- 按 `Ctrl+]` 断开、会话结束或宿主离线时，`ccr` 会取消上报，pane 回到普通 shell；再次接入后恢复。
- Herdr 恢复 pane 时会执行 `ccr claude resume <原生ID>`，有活跃进程时接回，离线时从历史恢复。没有原生 ID 时用 `ccr session attach <CCR会话ID>` 接入活跃进程（需要 Herdr 0.9.2 或更高，且 `ccr` 在 `PATH` 里）。
- 两种 Herdr 都支持，`ccr` 按环境自动选择：Herdr 终端版（环境里有 `HERDR_ENV`、`HERDR_PANE_ID`）通过它的 `herdr pane report-agent` 命令上报；Herdr 桌面版（`herdr-app` / `herdr-core`，命令行 `hc`，环境里有 `HC_TERMINAL_ID`）直接往终端写 [OSC 7501](https://mitchellh.com/writing/program-status-osc7501) 状态序列，不需要额外命令。设置 `CC_REMOTE_HERDR=0` 可全部关闭；`CC_REMOTE_OSC7501=1` 可在其它认 OSC 7501 的终端里强制启用。Herdr 不可用时静默忽略，不影响终端使用。
- 目前只支持 Claude Code 的终端会话，Codex 不在其中。设计说明见 [design/herdr-bridge.md](design/herdr-bridge.md)。

### 终端历史与导入

侧栏「终端历史」读取 Claude Code 本地的项目级 JSONL 记录（只读，不修改原文件）。可以「导入为托管会话」继续，导入前必须停止原终端进程；导入沿用原会话标题。

## 界面

- **会话列表**：桌面为左侧栏，手机为抽屉菜单，内容一致。显示执行中、等待操作、已完成、失败及终端会话是否在运行；后台会话持续刷新。打开过的会话标记「已缓存」，切换时保留消息、草稿、附件、滚动位置、工具展开状态和未提交的回答；点「×」释放缓存（会清除该会话的未发送草稿，宿主任务继续执行）。
- **工具调用**：运行中的工具调用显示已运行时长，每秒更新（工具组标题的「执行中」、展开后的那一行、子 agent 卡片和后台任务面板同样显示）；结束后显示总耗时。
- **翻看历史**：在对话里往上翻离开最新内容后，输入框自动收成一行，让出更多阅读空间（点它即恢复，正在输入时不会收起）；底部正中出现「↓」按钮，点击回到最新，Claude 仍在工作时按钮右上角有绿点。
- **侧栏**：可折叠；桌面端拖动右边缘调宽（200–480px，不超过窗口 40%，双击恢复默认，方向键每次 16px，宽度记在本机）。顶部显示宿主版本、Claude Code 连接状态和退出按钮；底部是「设置」和「服务状态」。
- **顶栏**：当前会话标题、项目目录，以及模型 · 推理强度 · 权限模式标签（继承值显示为「默认(…)」，`bypassPermissions` 标红，`dontAsk`/`auto` 标黄）、状态、刷新和「会话设置」。
- **输入**：Enter 或 Ctrl+Enter 发送（可选，会记住），Shift+Enter 换行，兼容中文输入法。输入 `@` 列出会话工作目录里的文件和目录（git 仓库遵守 `.gitignore`），继续输入筛选，↑↓ 选择，Enter 或 Tab 插入路径，Esc 关闭；选目录后继续列出其中内容。网络不稳时重发同一条消息不会让 Claude 收到两遍。
- **登录**：令牌保存在当前站点的 localStorage，刷新和重新打开无需重登；「退出」清除。

### 会话设置

点顶栏标签或齿轮打开。可修改模型、推理强度、权限模式（保存 / 取消 / 全部恢复默认），并显示会话 ID、Claude 会话 ID、目录、模式、创建时间和用量摘要。危险区提供「删除…」。

### 全局设置

侧栏底部「设置」分两部分：

- **CC Remote 默认**：新会话和 `ccr` 使用的默认模型、推理强度、权限模式。
- **Claude 用户配置**：可选直接写入 `~/.claude/settings.json`，会影响该账户下所有 Claude Code 使用。

生效顺序与写入细节见 [configuration.md](configuration.md#权限模式模型与推理强度)。

### 界面语言

网页和命令行支持简体中文和英文，默认跟随宿主的语言设置（安装时的 `--lang`，未设置时跟随系统）。网页可以在设置里为当前浏览器单独选择语言，不影响其它设备；命令行可用 `cc-remote service config --lang zh|en|auto` 修改服务的语言，或用环境变量 `CC_REMOTE_LANG` 临时指定。详见 [configuration.md](configuration.md#界面语言)。

### 订阅用量

侧栏底部显示 Claude 订阅的 5 小时额度和每周额度（与 Claude Code 的 `/usage` 相同），悬停可看重置时间和更新时间，点击打开「服务状态」中的详情：各额度（含单个模型的每周额度）的百分比、重置倒计时、套餐、更新时间，以及近 24 小时 / 7 天 / 30 天的用量曲线。

- 宿主用 Claude Code 自己的登录令牌（`~/.claude/.credentials.json`，macOS 为钥匙串，或 `CLAUDE_CODE_OAUTH_TOKEN`）向 Anthropic 读取，页面打开时最多每分钟一次，此外每 10 分钟后台读取一次以记录历史；历史保存在宿主数据库，保留 30 天。
- 只读取、不刷新令牌：令牌过期（Claude Code 长时间没运行）时显示上次的数据并注明，Claude Code 下次运行续期后自动恢复。服务端限流时显示上次的数据并稍后重试。
- 只适用于官方 Claude 订阅账号。Claude Code 配置了第三方 `ANTHROPIC_BASE_URL`（如国内模型的兼容接口）、Bedrock / Vertex / Foundry，或使用 API Key 时不读取任何数据，侧栏不显示，「服务状态」里说明原因。

### 通知

「设置 → 此浏览器」里可以打开系统通知（只对当前浏览器生效，打开时浏览器会请求通知权限）。会话需要你操作（权限审批、提问、计划确认）、执行完成、执行失败或终端会话的 Claude Code 中途退出时，弹出系统通知，三类可以分别关闭；点通知会回到页面并打开该会话。「执行完成」要等这一轮结束且子 agent、后台命令都结束才提醒；后台任务还在运行时 Claude Code 退出，算作退出。正在查看的会话不提醒。标签页标题前会显示等待你操作的会话数，如「(2) 主机名 · CC Remote」。

通知来自页面对会话列表的轮询，宿主不需要额外配置，但只在页面开着时有效（后台标签页、最小化也可以）。浏览器只允许 HTTPS 或 localhost 页面发通知；手机浏览器切到后台后通常会暂停页面，通知要等再次打开时才出现。

### 模型选择器

设置、新建会话和会话设置共用同一个模型选择器，可以输入任意模型 ID，也可以从列表选择。列表来自 Claude Code 官方别名、settings 中的 `model`/`availableModels`/模型类环境变量、本机会话最近使用的模型，以及配置了 API 密钥时的 `/v1/models`；缓存 10 分钟，可手动刷新。

### 删除会话

侧栏会话项的删除图标（桌面悬停显示，手机常显）或会话设置中的「删除…」。确认后删除 CC Remote 中该会话的消息、审批记录、终端记录同步标记和上传的附件；**不会**删除 `~/.claude` 下的原生 JSONL，仍可在「终端历史」中查看或恢复。执行中的托管会话需勾选「先停止再删除」；运行中的终端会话删除时会结束其 Claude Code。

### 服务状态

侧栏底部「服务状态」每 5 秒刷新：版本、PID、运行时长、监听地址（非本机地址标注「局域网可访问」）、服务托管方式、Claude 版本、会话与待审批数量、数据库/附件/日志占用、累计轮次/费用/tokens、近 14 天（UTC）轮次与费用图表、可排序的会话统计表（点击行打开会话），以及日志末尾 80 行（访问令牌和 Bearer 凭证自动隐去）。

轮次按用户消息计算；费用、tokens 和耗时来自托管会话的 Claude 结果事件，终端会话显示为「—」。

## 网页命令

在输入框输入：

| 命令 | 作用 |
| --- | --- |
| `/help` | 列出可用命令 |
| `/status` | 当前会话与宿主状态 |
| `/config`、`/permissions` | 查看配置与权限设置 |
| `/model [名称]` | 不带参数列出可用模型；带参数设置当前托管会话的模型。加 `--default` 改 CC Remote 默认，`inherit` 恢复默认 |
| `/effort [级别]` | 同上，针对推理强度 |
| `/permission-mode [模式]` | 同上，针对权限模式 |
| `/clear`、`/new`、`/reset` | （托管会话）开始新的 Claude 上下文，保留历史显示 |
| `/stop` | （托管会话）停止当前轮次 |
| `/compact [保留重点]` | （托管会话）压缩上下文，对话中显示压缩前后的 token 数 |

### Claude Code 原生命令（托管会话）

托管会话中，Claude Code 支持的其它命令都会原样交给 Claude 执行，包括内置命令（如 `/context`、`/usage`、`/init`、`/recap`）、插件命令和技能，hooks、frontmatter 等原生机制照常生效。输入 `/` 时的命令菜单就是 Claude 上一轮启动时报告的命令列表；Claude 不支持的命令会直接提示，不会消耗一轮对话。`/resume` 等只能在终端交互界面使用的命令不在列表中。


## 附件

- 点击「＋ 附件」、粘贴或拖放到输入框；支持任意类型文件。单个附件默认上限为 20 MiB，每条消息最多 8 个。在「设置 → 服务器 → 附件」可将宿主的单文件上限设为 1 到 256 MiB，保存后立即生效。
- PNG / JPEG / GIF 会校验内容（最多 2500 万像素）并显示缩略图；其它文件显示为文件卡片（名称、大小，可下载）。
- 文件保存在宿主数据目录 `uploads/<会话 ID>/`，文件名会清理（去掉路径和控制字符，最长 120 字节，保留扩展名）。
- 消息中会附上每个附件在宿主上的绝对路径和原文件名，提示 Claude 用 Read 工具读取（支持文本、PDF、图片、Notebook）；托管与终端会话相同，可能需要一次读取审批。
- 移除未发送的附件只是取消附加，文件仍留在宿主；删除会话时一并删除。目前没有其它自动清理。

## 查看文件

- Claude 消息里提到的文件路径（如 `docs/design/x.md`、`/home/me/app/main.go:12`、`C:\app\shot.png`）显示为链接，点开在查看器里查看；代码块和工具卡片的输出（如构建命令打印的产物路径）里的路径也一样。Read / Edit / Write 工具卡片展开后有「打开文件」按钮。
- Markdown 按格式渲染，可切换查看源码；其中的相对链接打开另一个文件（可返回），相对路径的图片直接显示。代码文件按语言高亮、显示行号，`:行号` 会标出并滚动到该行。PNG、JPEG、GIF、WebP、SVG 等图片直接预览；PDF 和其它无法预览的文件可以下载。文档里的 `#标题` 链接滚动到对应标题。
- 相对路径依次在文档所在目录、同一条消息（或文档、打开文档的那条消息）里出现的绝对目录、会话工作目录中查找。例如消息里写了 worktree 目录，其后的 `docs/...` 就在该 worktree 中查找。
- 只能打开会话工作目录，以及会话中出现过的目录、出现过的文件所在目录里的文件（符号链接按实际位置判断）；根目录、一级目录和用户主目录本身不会因为被提到而开放。超过 20 MiB 的文件不预览，但可以下载（不限大小，由浏览器直接下载；下载链接在下载过程中一直有效，再慢也不会中途过期，断开后 30 分钟内可以在浏览器里继续下载）；超过 2 MiB 的文本按纯文本显示，约 40 万字符以上的代码不高亮。网络共享路径（`\\host\share`）不会打开，以免宿主连接到其它机器。
- 图片在查看器里自己缩放：双指捏合、滚轮或双击（手机上双击屏幕）放大，放大后拖动查看，右下角的按钮缩小、放大或回到适应窗口。
- 网页终端里的文件路径同样可以点开。
- 终端历史（未导入的原生会话）不支持打开文件。

## 刷新与状态恢复

- 地址栏 hash 记录当前会话：托管 / 终端会话为 `#/s/<会话 ID>`，终端历史为 `#/native/<ID>`，欢迎页为空。可以收藏，浏览器前进 / 后退可在会话间切换。打开已删除或不存在的会话会回到欢迎页并提示「会话不存在或已删除」。
- 刷新后自动恢复：已打开的会话列表与当前会话、侧栏标签、每个会话未发送的输入、已上传未发送的附件、提问 / 计划 / 审批卡片里未提交的选择。保存在本浏览器 localStorage 的 `cc-ui:v1` 中，7 天未改动的草稿过期，总量约 1 MiB（超出时先丢最旧的）。
- 滚动位置（在底部时保持贴底）和工具展开状态只保存在当前标签页的 sessionStorage，关闭标签页即清除。
- 释放缓存或删除会话会清除该会话的本地草稿；退出登录清除全部 `cc-ui*` 数据。多个标签页同时编辑同一草稿时以最后写入为准。

## PWA

网页提供 PWA manifest 和静态资源缓存，可「添加到主屏幕」。PWA 安装与 Service Worker 通常要求 HTTPS（localhost 除外），通过局域网 HTTP 访问时界面可用，但可能无法安装。对话数据和 API 不进入离线缓存，不支持离线发送。
