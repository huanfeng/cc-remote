# 统一命令行入口设计：ccr

状态：已实现统一入口、双行终端选择器和供应商缓存用量摘要。2026-11-14。下文记录当前行为及兼容约定。

## 目标

`cc-remote` 与 `ccr` 是同一个命令的两个名称：相同参数、配置和运行环境下，行为、输出、退出码与副作用一致，包括无参数调用。文档优先使用较短的 `ccr`。不带管理子命令时，维持当前终端接力体验；带管理子命令时，直接管理 CC Remote。保留当前恢复会话、供应商选择、Claude 参数处理、终端输入输出和断线重连行为。

首轮统一用户入口与帮助，不更换数据目录、环境变量、服务名称、发布资产或实际后台文件名。`cc-remote` 是完整等价入口，不保留按程序名称区分的运行模式。

## 命令布局

| 场景 | 推荐命令 | 行为 |
| --- | --- | --- |
| 当前项目继续工作 | `ccr` | 选择当前目录的终端会话，没有则新建；宿主不在线时按现有规则自动启动 |
| 新建终端会话 | `ccr --new --model sonnet` | 保留 `--title`、`--effort`、`--permission-mode`、`--profile` |
| 恢复 Claude 会话 | `ccr --resume [ID或关键词]` | 保留 `-r`、`--resume=ID`；不带值时在当前目录选择 |
| 继续最近会话 | `ccr -c` / `ccr --continue` | 当前目录最近的 Claude 会话 |
| 最近终端会话 | `ccr ls` / `ccr list` | 保留当前跨目录列表和交互选择，不改成纯输出列表 |
| 接入指定会话 | `ccr <ID前缀或标题>` | 保留现有查询方式 |
| Claude 启动参数 | `ccr --add-dir ../lib --model sonnet` | 按现有规则新建宿主持有的终端会话 |
| 提示词启动 | `ccr -- "修复登录问题"` | 新建并发送首条消息 |
| 明确进入会话入口 | `ccr session [原ccr参数]` | 与当前 `ccr` 参数语义一致；同时提供会话帮助及保留字消歧 |
| 明确接入 | `ccr attach [参数] <ID或标题>` | 保留原 `cc-remote attach` 的行为和参数，保留缩写 `a` |
| 原生 Claude | `ccr claude [本工具参数] -- [Claude参数]` | 在当前终端直连原生 CLI，保留供应商注入和退出码；不创建宿主会话 |
| 状态与启停 | `ccr status/start/stop/restart` | 复用现有服务操作 |
| 日志 | `ccr logs -n 100 -f` | 复用现有日志实现 |
| 宿主配置 | `ccr config [参数]` | 查看、修改配置并按现有规则应用 |
| 服务生命周期 | `ccr service install/uninstall/...` | 完整保留 service 子命令，包括现有自动化参数 |
| 前台运行宿主 | `ccr serve --listen 127.0.0.1:8787` | 显式宿主入口，复用原宿主参数 |
| 供应商 | `ccr profile ls/default ...` | 保留现有供应商操作及 `--app` |
| OAuth | `ccr oauth ls/add/token/rename/rm ...` | 保留现有操作、认证和令牌输入方式 |
| 更新 | `ccr update [参数]` | 保留当前检查、指定版本、校验、更新及重启策略 |
| 启动器维护 | `ccr alias install/uninstall/status` | 作为兼容维护命令保留，日常帮助不突出 |
| 帮助与版本 | `ccr help` / `ccr --help` / `ccr version` / `ccr --version` | 根帮助与 CC Remote 版本；不自动启动宿主 |

不新增 `ccr install/uninstall` 顶层命令，减少会话标题的保留字；安装和卸载继续明确写在 `service` 下。不改变现有更新范围：重构 CLI 本身不扩展后台更新器为桌面更新器。

## 参数与分发规则

1. 两个名称进入同一个根分发器，不使用 argv[0] 选择功能。根入口只识别固定的子命令和帮助、版本选项；其余参数进入原有终端会话处理器，不通过宿主 FlagSet 解析。无参数时两个名称均进入当前目录的终端会话。
2. 仅允许将前置的连接上下文 `--host`、`--data-dir`（含 `=值`）提取后再识别子命令。必须按参数和值成对消费，不能把值里的 `status` 或 `config` 当作命令。
3. 一旦选择会话路径，不再从后续参数中寻找管理命令。例如 `ccr --resume status` 的 `status` 是恢复关键词；`ccr --model sonnet status` 保持原有会话参数语义。
4. `ccr -- status` 保持现有语义：发送 `status` 作为新会话首条消息。进入 `--` 后不识别管理子命令；会话处理器仍按原规则处理模型、恢复等选项。
5. 根管理保留字与会话标题重名时，使用 `ccr session status` 查询，或 `ccr attach status` 明确接入。不能承诺保留字标题在裸命令形式下仍不冲突；新增管理子命令后这一点需要写进迁移说明。
6. 已识别的管理命令参数有误时，返回该命令的错误与用法，绝不退回会话路径。例如 `ccr service typo` 不应创建会话。
7. `--data-dir` 继续指定本次操作的数据目录；`--host` 指定会话、OAuth、供应商请求的目标宿主。服务安装、启停、配置、日志和更新仍作用于本机，不因 `--host` 变成远程服务管理。根上下文中的 `--host` 不向本机服务 FlagSet 传递；文档需明确其作用范围。
8. 上下文参数优先级：用户显式参数高于启动器默认值，高于现有安装配置与环境变量默认值。重复参数时后一个覆盖前一个，兼容现有启动器前置默认值的形式。

不引入一套通用根解析器去吞掉所有未知选项，也不增加命令框架依赖。统一分发器返回目标处理器、上下文及原始剩余参数，执行层继续调用现有功能。

## Claude 参数兼容

以下命令维持当前语义：

```sh
ccr --resume
ccr --resume abc123
ccr -r abc123 --model sonnet
ccr --resume=abc123
ccr -c --effort high
ccr --new --profile oauth:work
ccr --add-dir ../lib --model sonnet
ccr -- "修复登录页"
```

裸 `ccr "修复登录页"` 继续作为会话标题查询；不在此次重构中悄悄改成提示词启动。

“兼容 Claude 常用参数”沿用当前支持范围：宿主终端模式继续拒绝宿主自己控制的参数，例如 `--settings`、`--session-id`、`-p`。需要完整原生参数时走直连入口：

```sh
ccr claude --profile work -- --resume abc123
ccr claude -- --help
ccr claude -- --version
ccr claude -- -p "检查这段代码"
```

根 `--help` / `--version` 用于 CCR；`ccr session --help` 用于终端接力；`ccr claude -- --help` 用于 Claude。直连分支必须在进入会话参数拆分之前识别，避免恢复、帮助等参数提前被会话处理器截获。

## 会话选择器：紧凑的终端界面

参考 [Herdr 的 agent 状态与工作区组织](https://herdr.dev/tui/docs/agents/)：状态显眼、任务标题突出、项目和运行信息次级展示。这里是 CCR 的选择器设计，不复刻完整的终端复用器。

`internal/terminal/picker.go` 负责双行条目和交互，复用 `/api/sessions` 的模型、供应商名称等字段，不为每个条目逐一请求详情。

### 展示样式

采用轻量、内联、双行条目；无需先进入全屏仪表盘。下例是布局示意，颜色由终端能力决定：

```text
CC Remote · 当前项目
~/workspace/cc-remote     5 个会话 · 2 执行中 · 1 等待回答

  进行中
› 1  ● 执行中    修复登录页                        刚刚
     Claude · Sonnet · 工作账号 · 0 个终端     a1b2c3d4
  2  ! 等待回答  检查数据库迁移                    2 分钟前
     Claude · Opus · 本机配置 · 1 个终端       e5f6a7b8
  3  ● 执行中    补充接口测试                      5 分钟前
     Claude · Sonnet · 工作账号 · 0 个终端     c3d4e5f6

  其他会话
  4  ○ 就绪      整理安装文档                      18 分钟前
     Claude · Sonnet · 本机配置 · 0 个终端     d4e5f6a7
  5  - 未运行    昨天的重构                        1 天前
     Claude · 模型未知 · 供应商未知             f6a7b8c9

  0  + 新建终端会话

↑↓ 选择  Enter 接入  / 筛选  0 新建  r 刷新  Esc 取消
```

- 第一行突出标题；状态和最近活动位置稳定。选中条目使用 `›` 与背景或反色高亮，默认推荐项另加标记，避免移动光标后丢失默认项含义。
- 第二行展示 agent、模型、供应商、终端接入数及短 ID。接入数是终端数，不称为用户数或所有客户端数。
- `ccr ls` 的跨目录列表在每个条目的第二行优先展示路径。较窄时按终端显示宽度截断，选中条目不额外展开，保持列表紧凑。
- 旧宿主缺少字段时显示未知，不把空供应商直接推断为本机登录，不展示令牌或供应商密钥。
- 只展示实际会话模型；未知或跟随默认而未确定时显示相应状态，不把当前全局模型冒充会话已经使用的模型。
- 首轮仍列出可接入的 Claude 终端会话。原生恢复列表复用排版，但使用原生历史数据可提供的字段；不把 Codex 托管会话混入终端列表，避免显示后不能接入。

### 状态、分组与排序

- 选中项反色高亮，等待或失败项使用警示色；状态均附文字，不依赖颜色或动态图标表达信息。
- 优先依据宿主实际在线状态和会话状态，避免把历史状态 `running` 的离线进程显示为正在执行。原生历史记录单独标记为可恢复，不推断进程在线状态。
- 将在线执行中和等待回答的会话归入“进行中”，其他会话归入“其他会话”；组内按最近活动排序。没有条目的组不显示。
- 当前目录列表保留目录限定；跨目录列表保持最近会话范围。原有最多 20 条的候选窗口先按最近活动选取，再进行展示分组；不因新分组突然加载全部历史。
- 原有默认候选仍按最近活动选取“尚无终端接入的会话”；全部已接入时默认新建。先确定默认候选 ID，再做展示分组，不能因为重新排序改变回车默认行为。
- 在一个选择周期内保持编号稳定。手动刷新保留选中会话 ID，重新生成编号并重绘；不后台重排导致正在输入的编号指向另一会话。选中条目已消失时提示并重新选择。

### 交互与兼容

- TTY 中支持方向键、回车、数字编号、新建和取消；进入 `/` 筛选后，按标题、路径、短 ID、供应商、模型进行不区分大小写的文本筛选。筛选不改变底层会话，不创建会话。
- 数字快捷选择保留多位编号输入，按回车确认；不能输入 `1` 时立即接入，导致无法输入 `10`。新建同样执行确认键，不在筛选文本中拦截字符 `0`。
- `/` 筛选时 Escape 先清除筛选或退出筛选；普通选择态 Escape 取消。筛选无结果显示空状态，回车不得隐式新建。
- 取消选择不停止会话，也不误入新建逻辑。宿主离线显示错误和重试提示，不把请求失败当成空列表。
- 多终端接入确认继续保留。输入和渲染只在选择器期间接管终端，退出、错误和 Ctrl+C 时恢复原始终端模式、光标和颜色。
- 支持 `r` 手动刷新，不增加后台轮询和持续重排。状态是读取时的快照，条目显示最近活动时间；以后如需自动刷新，仍需保持选择身份和编号稳定。
- 非 TTY、`TERM=dumb`、无交互终端使用无光标控制的文本列表及原有编号输入路径；EOF 没有有效选择时取消，不自动应用默认候选产生会话。尊重 `NO_COLOR`；没有颜色时状态文字和选中符号仍完整可读。
- 宽屏完整展示双行信息，窄屏优先保留编号、状态、标题并截断后续信息。中文显示宽度和 ANSI 序列分别处理，不按字节裁切；不要求 Nerd Font，不使用 emoji 作为对齐列。
- 所有标题、模型、供应商、路径均使用现有 `printable` 规则过滤控制字符后渲染；数据中的 ANSI 不得进入终端。
- 不引入新的 TUI 依赖。数据整理、纯文本/ANSI 渲染和键盘选择分别放在终端模块内可测试的位置，接入后的 PTY 转发和 Herdr 状态上报复用原实现。

## 供应商选择器：附带最新订阅用量

供应商选择沿用上述会话选择器的高亮、编号、筛选、窄屏与无色规则。在新建、恢复会话和 `ccr claude` 的供应商选择中，显示配置对应账号的最新缓存用量。显式 `--profile` 及非交互调用继续直接执行，不为展示用量额外弹出选择器。

### 展示样式

```text
选择供应商 · Claude

  0  沿用默认：工作账号

› 1  工作账号                  OAuth · 默认
     已用 5h 24% ↺2h · 7d 67% ↺3d · 采集2m前
  2  备用账号                  OAuth
     已用 5h 91% ↺35m · 7d 32% ↺5d · 采集8m前
  3  本机配置                  官方订阅
     已用 5h 18% ↺1h · 7d 42% ↺2d · 采集1m前
  4  团队 API                  API Key
     无订阅额度数据

↑↓ 选择  Enter 确认  / 筛选  r 重读用量  Esc 取消
```

每个供应商条目最多两行，包含选中态、加载态和错误态；条目之间不插入空白行。第一行展示编号、名称、类型及默认标记，第二行展示额度摘要、距重置时间、采集时间和必要的数据状态。`↺2h` 表示约 2 小时后重置；缺少重置时间时省略，不推算未知值。选中只改变高亮，不展开、不增加详情区。移除常驻进度条，完整窗口与精确重置时刻留在已有订阅用量页面。实际窗口来自后台，不能假设所有账号都提供 5 小时和 7 天。

窄屏按显示宽度精简：名称省略截断，第二行保留靠前的额度窗口和必要状态，仍不得自动折成第三行。安全过滤之后按终端单元格宽度裁切，颜色控制序列不计入宽度。

- 统一使用“已用百分比”，不混用剩余额度；精度遵循实际读数，未知值显示 `—`，不能显示为 0%。
- 额度使用短文本数值展示，选中高亮不改变额度含义，不因用量高禁用配置。
- 每个有数据的配置显示采集时间；失败、过期、未登录和身份未确认用短文本说明。失败但仍有上次读数时在第二行标记旧值和失败，不能伪装成刚刷新成功。长错误不在列表中展开。
- API Key 和第三方配置只在存在可靠且已有的对应额度数据源时显示其额度及单位；当前官方订阅采集不支持的配置显示“无订阅额度数据”。不把官方订阅百分比当成 API 余额、token 数或费用，不在本次重构里新增第三方余额查询脚本。
- 额度信息供选择参考，不自动改供应商、不因用量高自动禁用条目、不改变配置排序。用户仍能选择无用量或暂时不可用的配置，启动时沿用现有校验。
- 新建时默认项仍由供应商默认规则决定；恢复时编号 0 为“沿用原会话配置”，与全局默认分开。能解析到具体配置时显示对应缓存；无法解析则显示未知，不替换成其他账号数据。

### 账号关联与数据来源

当前监控按稳定账号 ID 去重，`monitorAccount.Profile` 是单个标记；同一官方账号可能同时出现在本机登录和多个 OAuth 配置中。因此不能只用 `Profile`、配置显示名称、列表顺序或“最新的一条 Claude 记录”进行关联。

后台提供批量、只读的缓存摘要接口 `GET /api/profiles/usage?app=claude`：返回 `{profiles: {配置ID: 摘要}}`，包含 `@native`。每项包含适用性、账号 ID（可确认时）、套餐、额度窗口、采集时间、过期/错误状态和关联状态；不含 token、配置环境变量、原始账号凭据或 token 指纹。当前只支持 Claude，其他 app 返回 400。

- 后台利用当前配置、当前登录凭据和已有账号绑定解析对应缓存；读取绑定本身不访问官方接口、不触发身份探测。没有可靠当前绑定时返回“尚无数据”，等待后台采样。
- 本机配置按实际生效的认证方式判断；本机环境若使用第三方端点或 API Key，不能展示磁盘上另一个官方登录的订阅额度。
- 多个配置指向同一账号时共用一份采集结果，可在第二行标记“共用额度”，不能把它们视作相互独立的额度池；关联名称过长时不在列表展开。
- 配置改名继续按 ID 关联；OAuth token 更换后先验证当前凭据的已有绑定，有稳定账号证据时延续同账号缓存和历史，否则显示待采样。不得仅因配置 ID 没变而沿用旧账号额度。
- 身份未确认但当前凭据有可靠独立缓存时可显示“当前额度 · 身份未确认”；不能据此与其他配置合并，也不能借用无关历史。
- 已移除配置、停止采集的旧绑定或与当前认证不符的缓存，不能作为当前供应商的最新额度。保留它们的历史不代表可以继续用于选择器。

### 加载与刷新

- 先展示供应商列表，缓存摘要异步填入；摘要失败或旧宿主返回 404 时保持原选择功能，显示“用量暂不可用”，不阻塞或清空配置列表。
- 每次打开选择器最多一次批量缓存读取，不逐配置请求官方 API。对摘要请求设置短超时，取消或确认后丢弃未完成结果，避免在 Claude 界面已经打开后继续打印。
- `r` 重新读取后台当前缓存，不强制刷新所有官方账号、不更改自动采样间隔。界面明确显示“采集于……”；不能把读取缓存的时间当作额度采集时间。
- 用量更新不重排条目，不改变默认或光标，不覆盖用户正在输入的筛选条件与编号。
- 非交互模式使用编号文本列表；`NO_COLOR` 禁用颜色。取消不执行启动、不更改默认供应商。

## 兼容旧入口与安装

- 新文档、帮助、安装完成提示均优先使用 `ccr`。产品和仓库仍叫 CC Remote。
- `cc-remote` 的现有管理子命令、`attach/a`、`claude`、`ccr` 继续有效。
- 旧式宿主调用（如 `--listen`、`--service-manager`）通过同一个兼容适配层转到宿主入口；两个名称均支持，不能仅给 `cc-remote` 保留特殊分支。只识别明确的宿主专用参数，`--data-dir` 等共用参数不能据此判定为宿主模式；不扫描 `--` 之后或已选定子命令之后的内容。新示例统一用 `ccr serve`，`cc-remote serve` 完全等价。
- `cc-remote` 无参数改为与 `ccr` 一样进入终端会话；原来的导航帮助通过任一名称的 `--help` 查看。这是明确的迁移变更，需要写入发布说明。
- 当前启动器会执行 `cc-remote ccr [预置连接参数] [用户参数]`。该分支升级为统一分发器，兼容已经安装但未重新生成的启动器，以及自定义数据目录和端口。
- 新生成启动器继续只负责进程启动和参数引用，业务分发放在 Go 内部。Windows `%*`、Unix `"$@"` 的参数边界、空格、Unicode 与进程退出码不得改变。
- 安装配置提供的默认宿主地址和数据目录由统一入口解析，两个名称使用同一默认值。新启动器不单独推导连接配置；旧启动器注入参数的兼容处理也不依赖程序名称，避免自定义端口下两种命令连向不同宿主。
- 真实后台文件继续使用 `cc-remote(.exe)`，发布压缩包、校验清单和更新器资产匹配维持现状。Windows `.cmd` 不直接作为计划任务的服务程序，也不新增一份需独立更新的后台二进制。
- `service.json`、数据目录、`CC_REMOTE_*` 环境变量、计划任务/systemd/launchd 标识保持现状，无需搬迁用户数据或重新登录。
- 自动启动宿主、服务监督进程、桌面端调用和 hooks/MCP 的内部调用必须继续有效。内部入口在正常用户路由之前处理，不得被当作会话标题启动。首轮不要求迁移已有内部调用格式。
