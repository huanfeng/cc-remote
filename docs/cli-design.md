# CC Remote 命令行设计

| 命令 | 行为 |
| --- | --- |
| `ccr` | 选择当前项目的终端，有需要时选择 Agent 新建 |
| `ccr ls` / `ccr list` | 跨项目选择近期活动的终端 |
| `ccr claude` / `ccr codex` | 接入当前项目所选 Agent 的终端，没有则新建 |
| `ccr claude --new` / `ccr codex --new` | 新建独立终端 |
| `ccr claude resume [原生ID]` / `ccr codex resume [原生ID]` | 恢复原生历史，省略 ID 时从当前项目选择，`--last` 选最近的 |
| `ccr local [claude]` | 在当前终端运行 Claude Code，可选 `--supplier ID` |
| `ccr session list [--agent claude或codex]` | 列出 CCR 会话和运行状态 |
| `ccr session attach <CCR会话ID>` | 按完整 ID 或唯一前缀接入活跃的 Agent 终端 |
| `ccr shell` / `ccr shell attach [ID]` | 打开当前项目默认 Shell，或选择一个已有 Shell 接入 |
| `ccr shell ls` / `ccr shell stop [ID]` | 列出或停止项目 Shell |
| `ccr run -- 命令 [参数]` | 在宿主运行一次命令 |

连接参数 `--host` 和 `--data-dir` 放在命令前。`--cwd`、`--new`、`--title`、`--prompt` 与支持的 `--supplier` 由 CCR 解析。`--` 后按原参数边界交给 Agent，宿主终端只接受该 Agent 支持的交互启动选项。Claude 和 Codex 的原生历史 ID 用在各自的 `resume` 命令，CCR 登记的 ID 用在 `session attach`。Shell 有自己的 ID，与 Agent 终端共享宿主接入方式。

Windows 和 Unix 的 `ccr` 启动器将参数直接转发给 `cc-remote`。服务安装和升级会重生成默认启动器。独立二进制的旧版原地更新保留安装目录中的脚本，可用新版 `cc-remote alias install` 重生成。

## 会话选择器：紧凑的终端界面

参考 [Herdr 的 agent 状态与工作区组织](https://herdr.dev/tui/docs/agents/)：状态显眼、任务标题突出、项目和运行信息次级展示。这里是 CCR 的选择器设计，不复刻完整的终端复用器。

`internal/terminal/picker.go` 负责双行条目和交互，复用 `/api/sessions` 的模型、供应商名称等字段，不为每个条目逐一请求详情。

### 展示样式

采用轻量、内联、双行条目；无需先进入全屏仪表盘。下例是布局示意，颜色由终端能力决定：

```text
CC Remote · 当前项目
~/workspace/cc-remote     5 个会话 · 2 执行中 · 1 等待回答

  进行中
› 1  ● 执行中    修复登录页                        刚刚
     Claude · Sonnet · 工作账号 · 0 个终端     a1b2c3d4
  2  ! 等待回答  检查数据库迁移                    2 分钟前
     Claude · Opus · 本机配置 · 1 个终端       e5f6a7b8
  3  ● 执行中    补充接口测试                      5 分钟前
     Claude · Sonnet · 工作账号 · 0 个终端     c3d4e5f6

  其他会话
  4  ○ 就绪      整理安装文档                      18 分钟前
     Claude · Sonnet · 本机配置 · 0 个终端     d4e5f6a7
  5  - 未运行    昨天的重构                        1 天前
     Claude · 模型未知 · 供应商未知             f6a7b8c9

  0  + 新建终端会话

↑↓ 选择  Enter 接入  / 筛选  0 新建  r 刷新  q/Esc 退出
```

- 第一行突出标题；状态和最近活动位置稳定。选中条目使用 `›` 与背景或反色高亮，默认推荐项另加标记，避免移动光标后丢失默认项含义。
- 编号独立成列、左对齐，按完整候选列表中的最长编号预留宽度；第二行缩进到第一行正文起点，筛选时不改变列宽。会话和供应商列表共用这一排版，选中项的两行一起高亮。
- 第二行展示 agent、模型、供应商、终端接入数及短 ID。接入数是终端数，不称为用户数或所有客户端数。
- `ccr ls` 的跨目录列表在每个条目的第二行优先展示路径。较窄时按终端显示宽度截断，选中条目不额外展开，保持列表紧凑。
- 旧宿主缺少字段时显示未知，不把空供应商直接推断为本机登录，不展示令牌或供应商密钥。
- 只展示实际会话模型；未知或跟随默认而未确定时显示相应状态，不把当前全局模型冒充会话已经使用的模型。
- 当前项目的终端选择器列出 Claude Code 和 Codex 的在线终端。跨项目的 `ccr ls` 也显示近期离线终端，选中后提示使用对应 Agent 的原生恢复命令。原生恢复复用排版，显示历史数据已有的字段。

### 状态、分组与排序

- 选中项反色高亮，等待或失败项使用警示色；状态均附文字，不依赖颜色或动态图标表达信息。
- 优先依据宿主实际在线状态和会话状态，避免把历史状态 `running` 的离线进程显示为正在执行。原生历史记录单独标记为可恢复，不推断进程在线状态。
- 将在线执行中和等待回答的会话归入“进行中”，其他会话归入“其他会话”；组内按最近活动排序。没有条目的组不显示。
- 当前目录列表保留目录限定；跨目录列表保持最近会话范围。原有最多 20 条的候选窗口先按最近活动选取，再进行展示分组；不因新分组突然加载全部历史。
- 原有默认候选仍按最近活动选取“尚无终端接入的会话”；全部已接入时默认新建。先确定默认候选 ID，再做展示分组，不能因为重新排序改变回车默认行为。
- 在一个选择周期内保持编号稳定。手动刷新保留选中会话 ID，重新生成编号并重绘；不后台重排导致正在输入的编号指向另一会话。选中条目已消失时提示并重新选择。

### 交互与兼容

- TTY 中支持方向键、回车、数字编号、新建和取消；进入 `/` 筛选后，按标题、路径、短 ID、供应商、模型进行不区分大小写的文本筛选。筛选不改变底层会话，不创建会话。
- 数字快捷选择保留多位编号输入，按回车确认；不能输入 `1` 时立即接入，导致无法输入 `10`。新建同样执行确认键，不在筛选文本中拦截字符 `0`。
- `/` 筛选时 Escape 先清除筛选或退出筛选，`q` 仍可用于搜索；普通选择态 `q` / Escape 取消。编号文本模式输入 `q` 加回车退出。筛选无结果显示空状态，回车不得隐式新建。
- 取消选择不停止会话，也不误入新建逻辑。宿主离线显示错误和重试提示，不把请求失败当成空列表。
- 多终端接入确认继续保留。输入和渲染只在选择器期间接管终端，退出、错误和 Ctrl+C 时恢复原始终端模式、光标和颜色。
- 支持 `r` 手动刷新，不增加后台轮询和持续重排。状态是读取时的快照，条目显示最近活动时间；以后如需自动刷新，仍需保持选择身份和编号稳定。
- 非 TTY、`TERM=dumb`、无交互终端使用无光标控制的文本列表及原有编号输入路径；EOF 没有有效选择时取消，不自动应用默认候选产生会话。尊重 `NO_COLOR`；没有颜色时状态文字和选中符号仍完整可读。
- 宽屏完整展示双行信息，窄屏优先保留编号、状态、标题并截断后续信息。中文显示宽度和 ANSI 序列分别处理，不按字节裁切；不要求 Nerd Font，不使用 emoji 作为对齐列。
- 所有标题、模型、供应商、路径均使用现有 `printable` 规则过滤控制字符后渲染；数据中的 ANSI 不得进入终端。
- 不引入新的 TUI 依赖。数据整理、纯文本/ANSI 渲染和键盘选择分别放在终端模块内可测试的位置，接入后的 PTY 转发和 Herdr 状态上报复用原实现。

## 供应商选择器：附带最新订阅用量

供应商选择沿用上述会话选择器的高亮、编号、筛选、窄屏与无色规则。在新建、恢复会话和 `ccr local` 的供应商选择中，显示配置对应账号的最新缓存用量。显式 `--supplier` 及非交互调用继续直接执行，不为展示用量额外弹出选择器。
